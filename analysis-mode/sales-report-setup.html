Sales Report setup

The Sales Report needs three things on top of the base installation: a sales semantic model built on navida's sales template, the Report Code SALES on that model's row, and the Sales Analysis licence for every report user. This page walks through them, lists what the model must contain, and explains the messages you may see on the way.

Before you start

  • The base installation is complete — the app is installed, admin consent granted and Test Sign-In succeeds (Install, panels 1 and 2).
  • A sales semantic model built on navida's sales template: the BC2Fab Sales model from your Microsoft Fabric workspace, or navida's NAVBI sales model connected directly to Business Central. Other models work when they carry the same tables and measures — see What the model must contain.
  • Read and Build permission on that model for every report user, exactly as for analyses.
  • Sales Analysis licences — purchased with the app on AppSource; the plan includes the analysis mode, so a report user needs no second licence. Sandboxes are not licence-enforced.
  • Optional, for the AI cards and Ask your data: the Azure OpenAI resource configured for Copilot (Install, panel 4). Without it the report works completely; only the AI cards and the chat are absent.

Set-up steps

1 · Register the sales model

Done once per environment, by an administrator, on Power BI Analysis Models.

1
Choose Add Model…, pick the workspace and the sales semantic model. If the model is the one behind Business Central's own Power BI sales report, Get Standard Reporting Models does the same in one go: it adds the models of the Power BI Reports Setup (Finance, Sales, Purchases, …) once each and loads their metadata. Resolving a report's model needs the delegated Power BI permission Report.Read.All, so a consent dialog may appear the first time.
2
Choose Test Connection on the row — a token is acquired and a minimal query runs against the model.
3
Choose Refresh Model Metadata to take number formats and field translations from the model definition. The user who runs it needs write permission on the model; one refresh serves everyone.
Models installed as a Power BI template app (the NAVBI sales model among them) do not allow the definition export. The report then formats by data type; maintain currency and percentage formats under Format Strings on the row — manual entries always win.

2 · Link the model with the report

One model per report code; the code is what Tell Me and the role centers open.

1
On the model's row set Report Code to SALES. Get Standard Reporting Models sets it automatically on the sales model when no model carries the code yet.
2
Choose Open Report on the row. The report validates its definition against the model on opening; if a table or measure is missing, it says which.

3 · Licences and permissions

Per user, by an administrator.

1
Assign a Sales Analysis licence in the Microsoft 365 admin center under Billing → Licenses. A user with this plan needs no Analysis Mode licence in addition.
2
Assign the permission sets NBI Analysis User and NBI Sales Analysis. The second one holds the objects of the report only; the first one everything shared with the analysis mode.
3
Without the plan the report page shows a message naming the missing plan instead of the report. Delegated administrators (CSP partner roles) have access without consuming a licence.

4 · Open the report

By each report user.

1
On the Business Manager, Sales & Relationship Manager, Order Processor or Accountant role center choose Sales Report (Power BI) under the reporting actions — or search for it with Tell Me. Both open the model that carries the code SALES.
2
On first use one Microsoft sign-in window may appear; afterwards sign-in is silent. The report opens with the period year to date up to the last closed month and all companies.
3
Set the report year, the cut-off month and the companies in the slicer bar. The state is remembered for you and this model.

5 · AI cards and Ask your data (optional)

Nothing separate to configure.

1
The Azure OpenAI resource, deployment and key entered for Copilot on Power BI Analysis Setup serve the report as well, with Enable Copilot switched on and the capability active under Copilot & agent capabilities.
2
By default AI cards are stored per model and shown to every reader whose data produce the same figures. Switch AI Texts per User on the setup page if every user should get cards of their own.
3
Delete AI Texts on the models page removes the stored cards of a model, for example after the model was reloaded.

What the model must contain

The report definition names tables, columns and measures of navida's sales template. Measures are found by name in whichever table hosts them, so the BC2Fab and the NAVBI variants of the template both work unchanged. Captions and number formats come from the model at runtime. Optional objects improve the report when present and are skipped when absent.

ObjectUsed for
Measures Net Sales, Order Income, Profit Margin, Profit Margin 2 %, New Customer's Net Sales, Active Customers, Discount %, Order Backlog (key date), Expected Net Sales The nine KPI tiles and the detail sections.
Measures Invoice Amount, Sales Discount, Credit Amount, Existing Customer's Net Sales, Direct Costs, Credit Ratio _ %, Ø Net Sales per Customer The calculation scheme.
Table Date with Date, Year, Month Number Period slicer, trend charts, cumulative chart.
Table Company with Company Code, Company Name Company slicer, per-company view, default breakdown of the free analyses.
Table Facts with Prepayment Type, Posting Date Base filter of the sales model (prepayment documents excluded) and Data as of.
Optional: comparison variants … PY, … YOY, … YOY % per measure Used when present; otherwise the report defines the comparison inside the query.
Optional: field parameter table Chart Dimension 1 The dimension catalog of the breakdown picker; without it, the model's columns are offered.
Optional: Company Name, Customer Name (Sell-to), Product Hierarchy Level 1, Salesperson Name (Document) Driver dimensions of the AI cards — the largest movers per KPI. A missing column drops that dimension.
Optional: measure No. Rows in Facts Presence condition of the value lists in the filter drawer; Net Sales is used otherwise.

If something does not work

What you seeWhat it means
“No semantic model is linked to a report yet. Set the Report Code on the Power BI Analysis Models page.” No model carries the code SALES. Set it on the sales model's row (step 2).
“The sales report is part of the "Sales Analysis" plan …” The user has no Sales Analysis licence. Assign one in the Microsoft 365 admin center (step 3). In sandboxes the message never appears.
“The report definition references fields this model does not have” The model is not built on the sales template, or measures were renamed. The message lists the missing objects — compare with What the model must contain.
“KPIs could not be loaded” The query failed: the user is missing Build permission on the model, or the tenant setting Semantic Model Execute Queries REST API is switched off. Test Connection on the models page shows the underlying error.
Amounts without currency, percentages as decimals No format refresh has succeeded, or the model is a template app that refuses the definition export. Run Refresh Model Metadata, or maintain the formats under Format Strings.
The role center action opens the wrong model The code SALES sits on another row. A code can be linked to one model only; move it.
Add AI interpretation and the ✦ are missing Copilot is not enabled: endpoint, deployment and key on the setup page, Enable Copilot on, and the capability active under Copilot & agent capabilities. The setup page shows a status line for each.
A colleague sees an AI card, you do not Expected: cards are shared only among readers whose data produce the same figures. Request your own card, or let an administrator switch on AI Texts per User.
